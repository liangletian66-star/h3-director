# 调参笔记

这台机器上跑出来的实测数据，不是估算。硬件：RTX 5050 Laptop **8GB** + 16GB RAM + Windows 11，ComfyUI 0.3.x，int8 混合精度权重。

## token 预算：8GB 卡的真正约束

H3 一次采样吃多少 token：`(W/16) × (H/16) × ((帧数-5)//17 × 5 + 2)`。

124 帧 → latent 时间步 37。

| 分辨率 | token | 8GB 能不能跑 |
|---|---|---|
| 704×384 | 39,072 | ✅ 低档，稳 |
| 768×432 | 47,952 | ✅ 中档，稳 |
| 1152×640 | 106,560 | ✅ 高档第二采 |
| 1280×704 | 130,240 | ⚠️ 高档第三采，离硬限只剩 3,000 |
| 1280×720 | 133,200 | ⚠️ 踩线，不稳（720 不是 16 的倍数，H3 会自行调整） |
| 1920×1088 | 301,920 | ❌ 硬限的 2.3 倍，必 OOM |

**结论**：8GB 卡的原生上限就是 1280×704 这一档。`@res 1080p` 是后处理放大，不占生成预算。

## 档位实测

同 prompt、同 seed、同 124 帧：

| 档位 | 生成路径 | 单段耗时 | 相对画质 |
|---|---|---|---|
| 低 | 704×384 / 4 步 / LoRA | 110 秒 | 基准；毛发略糊，其余无劣化 |
| 中 | 768×432 / 8 步 | 176 秒 | 细节干净，台词清晰 |
| 高 | 768×432 → 1152×640 → 1280×704 | 648 秒 | 比中档细节 +10~15%，差异「小到中」 |

高档三采的账：48k → 106k → 130k token，耗时是单采的 3.6 倍。值不值得看你拍什么 —— 特写、收藏级成片值得，日常镜头不值。

## 裂缝与接缝

两段接力实测：seg00 106.7 秒 + seg01 96.1 秒 + 拼接，合计 3.4 分钟出 10.2 秒（245 帧）。接缝 full 0.866 / struct 0.972。

另一轮 5 参考图 + 两段接力：4.5 分钟，full 0.895 / struct 0.962。

接力帧本身要经过「抽末帧 → lanczos 缩回生成分辨率 → 模型重建」三步，所以任何指标都到不了 1.0。判定标准见下一节。

## 接缝分数：全分辨率 SSIM 会骗人

一开始用原分辨率 SSIM，低于 0.85 就报警。结果栽了：三段古寺镜头（瓦片 + 雾 + 树叶），接缝肉眼几乎逐像素一致，SSIM 却报 0.742 / 0.781，全是误报。

原因很直接：SSIM 是逐像素的局部结构相似度，高频纹理（瓦楞、树枝、雾气颗粒）只要有一点点重绘差异就会把分数压下来 —— **画面越丰富，分数越低**。这指标天然惩罚高质量画面。

改成两级：

| 指标 | 算法 | 用途 |
|---|---|---|
| `full` | 原分辨率 SSIM | 只作参考，不作为判定 |
| `struct` | 缩到 160×160 再算 SSIM | **判定用**，滤掉高频噪声只剩构图与色调 |

实测对照（同一批接力，全部肉眼连贯）：

| 场景 | full | struct |
|---|---|---|
| 静谧猫特写 | 0.866 | 0.972 |
| 人物中景 | 0.895 | 0.962 |
| 古寺瓦片 + 雾（接缝1） | 0.742 | 0.924 |
| 古寺瓦片 + 雾（接缝2） | 0.781 | 0.940 |

所以警戒线定在 **struct < 0.90**。按旧阈值，上面两条好镜头会被判成漂移，反而掩盖真正的断裂。

真要看断言还是看 `seam_check/` 里抽出来的前后帧 —— 数字只是提醒你去瞄一眼。

## 踩过的坑

**1. 低分辨率必出字幕。** 同参考图、同 seed、同台词句式，704×384 画面底部出对白字幕，768×432 一帧都没有。低分辨率落在训练分布里「低清 = 带字幕压缩剧集」的区域，模型看自己在生成压缩剧集，自动配字幕。`@negative 字幕` 只能把大字压成小字，`@wide 2.35` 裁切才是根治。

**2. 4 步蒸馏 LoRA 蒸坏了音频分支。** 同一句台词，低档含混到听不出字，中档 ASR 能完整转写。要人声就用中档以上。

**3. 参考图带字幕条会加重字幕倾向。** 从成品剧集截的参考图，底部字幕条本身就是「这画面该有字」的强先验。用前先裁。

**4. `@res` 的响度不是 `volume=-18dB`。** 这个值是**响度目标**，要用 `loudnorm=I=-18:TP=-1.5:LRA=11` 归一，写成 `volume=-18dB` 是再压 18dB，安静的段落直接压成无声。

**5. 首尾帧模式下参考图被忽略。** 同一个节点两种模式，互斥。参考图只在第一段用。

**6. 代理环境连不上 ComfyUI。** 系统开着 HTTP 代理时，`127.0.0.1:8188` 会被送进代理。`h3core.py` 导入时直接摘掉 `http_proxy` 等环境变量，并设 `NO_PROXY=*`。

**7. Windows 上子进程会继承 HTTP socket。** 可视化后端用 `Popen` 拉子进程时如果不加 `close_fds=True`，HTTP 连接的句柄会被继承，客户端等不到响应结束。

## 档位选择的决策顺序

1. 这段有台词 / 要人声 / 怕字幕？ → **中档**，没得商量
2. 无对白、纯环境镜、打斗过渡？ → **低档**，省 1 分钟
3. 是特写 / 是收藏级成片 / 细节要满？ → **高档**，等 11 分钟
4. 交片要求 1080p？ → 加 `@res 1080p`（任何档位都能加，但高档放大后最耐看）
